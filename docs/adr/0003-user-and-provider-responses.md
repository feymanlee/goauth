# 统一返回 User 并保留平台资料与令牌

最初的认证结果只保留身份和有限资料。根据后续明确的通用用户需求，`Exchange` 和 `Verify` 改为返回 `User`，提供 `id`、`nickname`、`name`、`email`、`avatar`、`raw`、`token_response`，同时保留平台和应用作用域。此决策替代设计记录中“结果默认不包含令牌或原始响应”的约定。

保留原始资料和 token 响应，使接入方能够读取平台特有字段、访问令牌与刷新令牌，而不必扩大公共资料模型。代价是完整 `User` 包含凭据；只需要身份的业务可以使用 `User.Identity()`，账号绑定仍使用带作用域的 `User.Key()`。

规范化 ID 使用字符串，避免 OpenID 与数字 UID 的类型差异；原始响应里的数字则无损保留。抖音只保留响应的业务 `data`，支付宝只保留验签通过的业务对象。QQ、微博没有服务端换码结果，仅保留已验证的输入访问令牌，不制造不存在的授权范围或刷新令牌。

资料仍由 `FetchProfile` 显式启用；未请求时 `raw` 为空对象，资料字段为空字符串。任何认证或已请求的资料步骤失败都返回零值 `User`，不交付未验证或部分完成的用户结果。
